# sts-x v5.1 Migration Note — 下游调用方必读

> **日期**: 2026-08-01  
> **适用版本**: v5.1 (commit `80cf900`, 对外版本号仍 `3.2.0`)  
> **影响范围**: 所有消费 `sts-x` JSON 输出的客户端（MCP client / 脚本 / agent / IDE 插件）  
> **严重度**: ⚠️ 中等 —— 不改代码会崩的才需要动，大多数调用方无感

---

## 一、变更摘要

v5.1 核心改动只有一处：**0 命中时 AI 自救引导**（`build_hint` 双语言动态提示）。
由此引入两个新增字段 + 一个类型变更：

| 字段 | 类型变更 | serde 行为 | 何时出现 |
|---|---|---|---|
| `hint` (SearchResponse / AiLocateOutput) | **新增** `Option<String>` | `skip_serializing_if = "Option::is_none"` → **None 时字段从 JSON 中完全消失** | 仅 locate 搜索 0 命中时 = `Some("...提示文字...")`；其余情况 = `None`（字段不存在） |
| `_ai_instructions` (AiSearchOutput / AiFileOutput) | `String` → **`Option<String>`** | 同上 → **None 时字段完全消失** | **仅 expand / file 模式携带；locate 模式结构里根本没有此字段**。expand 恒为 `Some(string)`：有命中 = `AI_HINT` 使用指南长串（`"I am STS-X {version}..."`），0 命中 = 自救提示串（query 含中日韩→中文，否则英文）。`--no-hint`(CLI) / `hint:false`(MCP) 时 = `None`（字段消失）。**绝不会是空串 `""`** |

### 关键语义

```
skip_serializing_if = "Option::is_none" 的含义：
  Some(xxx)  → JSON 里出现:  "hint": "xxx"
  None       → JSON 里消失:   （根本没有 "hint" 这个 key）
  
⚠️ 不是变成 null！是 key 都没了！
```

## 二、谁需要改代码

### ✅ 不用改（无感）

1. **只看 `results[]` / `total_hits` / `search_time_ms` 的客户端** —— 这些字段没动
2. **expand 模式用户** —— `hint` 只在 locate 模式 0 命中时触发，expand 模式不走
3. **tally.py / 统计脚本** —— 不依赖 `_ai_instructions`
4. **WorkBuddy 调用侧（已适配）** —— 0 命中自救链读 `hint` 时已做 `as_str().unwrap_or("")` null 安全

### ⚠️ 必须改（会崩或拿到错值）

1. **硬解析 `_ai_instructions: String` 的旧代码**
   - **症状**: v5.1 下该字段可能**直接消失**（key 不存在），按 `String` 反序列化不会报错（serde 会忽略未知缺失字段），但如果代码显式 `.get("_ai_instructions").unwrap()` 或 `resp["_ai_instructions"].as_str().unwrap()` → **panic / unwrap on none**
   - **修复**: 改成 `.get("_ai_instructions").and_then(|v| v.as_str()).unwrap_or("")`

2. **硬解析 `hint: String` 的 locate 模式消费者**
   - **症状**: 正常搜索结果里根本没这个 key（只在 0 命中时出现）
   - **修复**: 同上，`.get("hint").and_then(|v| v.as_str()).unwrap_or("")`

3. **非 WorkBuddy agent / 自定义 MCP client / bat 脚本里的 JSON 解析**
   - 如果有任何 `["xxx"]` 直接取值而不做 exists 检查 → 需加防御

## 三、各语言适配示例

### Python
```python
# ❌ 旧写法（v5.1 可能 KeyError）
instructions = resp["_ai_instructions"]  # key 不存在时 KeyError

# ✅ 新写法（v5.1 安全）
instructions = resp.get("_ai_instructions", "")  # 或 .get("_ai_instructions") or ""
hint = resp.get("hint", "")
```

### Rust (serde_json::Value)
```rust
// ❌ 旧写法
let instr = resp["_ai_instructions"].as_str().unwrap(); // None 时 panic

// ✅ 新写法
let instr = resp.get("_ai_instructions")
    .and_then(|v| v.as_str())
    .unwrap_or("");
let hint = resp.get("hint")
    .and_then(|v| v.as_str())
    .unwrap_or("");
```

### JavaScript / TypeScript
```js
// ❌ 旧写法
const instr = resp._ai_instructions; // undefined，后续字符串操作可能异常

// ✅ 新写法
const instr = resp._ai_instructions ?? "";
const hint = resp.hint ?? "";
```

### Shell / jq
```bash
# ❌ 旧写法（jq 报错 exit 1）
instr=$(echo "$resp" | jq -r '._ai_instructions')

# ✅ 新写法
instr=$(echo "$resp" | jq -r '._ai_instructions // ""')
hint=$(echo "$resp" | jq -r '.hint // ""')
```

## 四、MCP 协议层细节

MCP `search` 工具新增参数：

| 参数 | 类型 | 默认值 | 含义 |
|---|---|---|---|
| `hint` | boolean | `true` | 设为 `false` 可抑制 `_ai_instructions` 输出（省 token） |

当 `hint=false`：
- `AiSearchOutput._ai_instructions` = `None` → JSON 中不出现
- 其他字段不受影响

当 `hint=true`（默认，仅 expand / file 模式）：
- `_ai_instructions` = `Some(build_hint(...))` → JSON 中出现**非空字符串**：有命中时是 `AI_HINT` 使用指南长串，0 命中时是自救提示串。**不是空串**。
- locate 模式无 `_ai_instructions` 字段，`hint` 参数对其无效。

**MCP 客户端不需要改**（除非你显式传了 `hint=false` 又去读那个字段）。

## 五、验证清单

升级到 v5.1 后，下游调用方可跑以下检查：

1. [ ] locate 搜索**有结果**时：JSON 里**没有** `hint` key ✓
2. [ ] locate 搜索**0 结果**时：JSON 里**有** `hint` key，值为非空字符串 ✓
3. [ ] expand 搜索任意查询：JSON 里**没有** `hint` key ✓
4. [ ] expand / file 搜索不传 `hint` 参数：JSON 里**有** `_ai_instructions`，值为**非空字符串**（有命中=AI_HINT 指南；0命中=自救串）✓
5. [ ] locate 搜索任意查询：JSON 里**永远没有** `_ai_instructions` key（该模式无此字段）✓
6. [ ] MCP expand/file search 传 `hint=false`：JSON 里**没有** `_ai_instructions` key ✓
7. [ ] 你的代码对以上所有情况的 JSON 做 `get(key).or(default)` 解析 → 不崩溃 ✓

## 六、不变的部分（放心用）

以下字段/行为与 v5.0 **完全一致**，无需任何适配：

- `query`, `results[]`, `total_hits`, `search_time_ms` —— 类型、结构、语义全不变
- `locate_matches[]` —— Vec<LocateMatch> 结构不变（`skip_serializing_if = "Vec::is_empty"` 是旧逻辑）
- `multi_hop` —— 同上，Option<Vec> + skip 逻辑不变
- CLI 输出格式（`--json` flag）—— 变更只影响 JSON 内容，不影响 CLI 文本输出
- `sts-x mcp` 子命令 —— stdio 协议不变，工具 schema 向后兼容（新参数有默认值）
